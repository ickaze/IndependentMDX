# Random LFO arithmetic — IndependentMDX 0.33.4

この文書は0.33.4時点の記録です。近似生成器は0.33.5で置き換えられました。[現在の生成式と検証](RANDOM_LFO_0.33.5.md)を参照してください。

検証日: 2026-10-12

## 対応範囲

ランダムLFOの振幅計算・更新間隔を修正しました。**乱数生成器自体は近似であり、比較対象と同じ数列は生成しません。** 取得済みの乱数列をテーブルとして埋め込んでいません。他者のドライバー実装ソース、逆アセンブル、実行ファイルの解析は使用せず、独自MDXと出力レジスタログのみから演算を調べました。

## ログから確認した演算

乱数出力を符号付き16ビット値 `r`、波形+4の展開後の深さを `d` とします。

- MP: `d` の下位8ビットを符号付きに解釈した値 `s` を使用します。音程変位（1/64半音単位）は `floor(r*s/256)`。深さ128/255/256/257は−128/−1/0/1です。実装では小数部を保持し、最終的な音程レジスタ変換で床関数を適用します。
- MA: `floor(r*d/256)` の下位8ビットを減衰量として取り出し、通常のTLへ加算して127でクリップします。負の積はゼロ方向への切り捨てではなく床関数です。
- ランダムの振幅に周期は掛けません。周期は更新間隔です。
- MPは最初の進行クロック、その後は指定周期ごとに更新。MAは1周期経過後から更新します。MAの設定直後の変位は `max(0,-d)`（8ビット小数部付き）です。

68入力を2回ずつ記録したレジスタ状態は一致しました。深さ93/95の複数デチューンとMAの複数深さを組み合わせ、511個の符号付き16ビット出力を一意に復元しました。深さ境界のMP/MA各17入力・512クロックで、それぞれ8,704点が上記の計算モデルと一致しました。復元に使っていない既存MP/MA各3入力（深さ1/8/−8、周期1、各384クロック）も一致しました。

この一致は、復元した乱数を与えた**演算モデル**の検証です。製品の近似生成器が同じ値を出すことを意味しません。取得したログ自体は配布物に含めません。

## 製品の乱数状態

既存の独立実装の整数ミキサーを使い、16ビット符号付き値を生成します。曲ごとのカウンターを持ち、チャンネル処理順に値を取り出します。同一トラック内ではMP、MAの順です。以前の各チャンネルで同じ位相から同じ値を直接算出する方式を廃止しました。

曲開始とシーク時の再構築は同じ初期状態から行うため再現可能です。MP/MA同時使用、遅延、再設定を含めた全条件での参照ツールの乱数消費順は未確定です。一般的な線形合同法などの候補は取得列と一致せず、生成式を特定できていません。

## 再出力ログの比較

Signed_Probeは比較可能58入力中52一致・6不一致です。0.33.3から増えた4一致は、MP3の深さ±256とMP7の深さ±1が変位ゼロとなるケースです。乱数生成式が一致したことによる改善ではありません。MA4～7の12入力は比較対象ログがありません。結果は `LFO_SIGNED_0.33.4.csv`。

既存LFO_Comparisonは76入力中32一致・44不一致で、従来一致していた31入力は一致を維持しました。結果は `LFO_COMPARISON_0.33.4.csv`。この比較は所定クロックの対象レジスタ状態であり、全イベントや音声の完全一致ではありません。

## 検証と制限

- ネイティブReleaseのCTestで5/5スイート成功。深さの境界、負の積の丸め、MP/MAの周期境界と値の保持を検証しました。
- Windows x64 GUI/CLIとx86ブリッジをクロスビルド。デバッグ情報・制作環境パス・外部C++ランタイム依存を検査。Windowsでの実行、GUI操作、聴感比較は未実施です。
- 設定形式・ライセンス・音源DLLは変更していません。音源DLLは置き換え可能な既存構成を保持しています。
- 既存MRL/MRZのイベントは変更しません。今回の処理を記録するにはMDXから再出力してください。

追加のログ再取得は現時点では不要です。`LFO_Random_Depth_Probe` の入力と取得手順は再現用として保持しています。
