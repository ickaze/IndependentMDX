# C86CTLとポルタメント — 0.17

## C86CTLの調査結果

アプリ内の音色変更処理（MDXの@）に、チップ全体のresetやSleepはありませんでした。予定時刻まで待つ送信キューは従来からのFM遅延・音声同期用です。停止、終了、一時停止の切替、シーク時のresetは必要な既存処理として維持しています。c86ctl.dll内部やUSB転送の待ち時間は、この環境では実測できていません。

旧版には実機で不適切な中間状態を作る送信順がありました。

1. 新しいアルゴリズムを出力が開いたまま設定する。
2. 音色定義そのままのTLを書き込む。
3. 曲の音量を加算したTLを再度書き込む。

さらにC86CTL側はパン／フィードバックだけの書き込みでも、保存していた4オペレーター分のTLを再送していました。実機ではレジスタの転送が逐次行われるため、これらの間に補正前の大きな音や未完成の音色が出る可能性があります。ハードウェア録音による原因の確定はしていません。

0.17ではC86CTL向けの音色変更中だけ該当チャンネルのL/R出力を閉じ、最終TLを含む音色を設定してから出力を戻します。エンベロープを初期化する追加キーオフ／リセット、固定待機は入れません。パン／フィードバックだけの変更ではTLを再送せず、同じTL値も送信を省きます。アルゴリズムやgain変更で必要なキャリア音量の更新は行います。MIDIの発音・音色変更・状態復元も同じ音色設定手順です。

瞬時の音色・パン切替そのものに伴うクリックを完全に消す処理ではありません。実機で従来の大きなノイズが解消したか確認が必要です。

## クオンタイズとポルタメント

旧版ではポルタメント累積値の更新もキーオン中に限定していました。このためq1で早くキーオフすると、音符後半のリリース音がその時点の音程で止まりました。

0.17では「キーオンか」ではなく「ポルタメント付き音符の時間がまだ残っているか」で更新します。キーオフしていても音符の終端まで音程が変わり、休符・曲末で止まります。ソフトウェアLFOとは独立した判定です。

再現例:

```text
q1 o7g1_<g&g1_<g&g1_<g&g1_<g
```

元のMMLコンパイラは同梱していません。回帰テストは対応する4回の下降・タイを独自生成したMDX命令で再現し、q1とq8のKC/KF更新列が同一であること、q1のキーオフ後にも更新があること、休符／曲末後は更新されないことを確認します。元のコンパイラ出力との完全一致を主張するものではありません。

## 検証範囲

Linux上のソースリンク版で回帰テスト62グループ通過。C86CTL送信前のレジスタ変換は実際に使用するC86Gainを仮の出力先へ接続して検証しました。Windows GUI/CLIとGUIテストはクロスビルド済みです。Windows GUIテストの実行、C86CTL実機およびUSB転送の録音検証は未実施です。
