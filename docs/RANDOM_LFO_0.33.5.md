# Software LFO RNG — IndependentMDX 0.33.5

検証日: 2026-10-12

## 生成式

曲開始時の状態を `state = 0x1234` とし、乱数を1つ取り出すごとに次を実行します。

```text
product = state * 0xC549 + 0x0C
state   = product & 0xFFFF
random  = signed16((product >> 8) & 0xFFFF)
```

`product` は32ビット符号なし整数です。次の内部状態は下位16ビットですが、出力には**切り詰める前の積和結果のビット8～23**を使います。切り詰めた状態をシフトする式とは異なります。実装は `src/lfo_random.h`。記録済みの乱数テーブルを再生する仕組みではありません。

## 独立に導いた方法

独自生成MDXのレジスタ出力だけを比較しました。他者のMXDRV実装ソース、逆アセンブル、実行ファイルの内部解析は使用していません。

1. MP3の深さ93/95と複数デチューンで音程のクリップと量子化を分離し、MA3の異なる深さで残る候補を絞り、511個の符号付き16ビット値を一意に復元しました。
2. 単純な出力値同士の線形合同式では一致しなかったため、内部状態と出力値を分離して探索しました。下位ビットの周期から、状態の一部だけを出力している候補を検査しました。
3. 4の倍数となる内部状態を4で割った表現では、14ビット状態の更新が `state14 = (1353 * state14 + 3) mod 16384`、初期状態1165となりました。出力の残りのビットも使い、上記の16ビット状態と完全な積和結果を使う式へ絞り込みました。
4. 復元した511個全てと一致。さらに、式の探索に使用していない既存の周期違い・複数チャンネル・遅延・再発音・休符・ON/OFFのログと照合しました。

有限の観測から元実装の内部コードや式の数学的な唯一性を証明したわけではありません。取得した条件で動作互換となる生成式を特定した、という検証結果です。

## 深さとタイミング

0.33.4で導入した演算を維持します。MPは展開後の深さの下位8ビットを符号付きとして使い、MAは乗算後に8ビットの減衰量を取り出します。周期は振幅に掛けません。MPは最初の進行クロック、MAは1周期経過後から値を更新し、更新間隔中は保持します。

乱数状態は曲全体で共有し、チャンネル順、同一チャンネルではMP→MAの順で取り出します。曲開始とシーク再構築は同じ初期状態から処理します。取得済みの複数チャンネル入力では一致していますが、全てのMP/MA同時使用パターンを網羅した検証ではありません。

## 音程の16ビット桁あふれ

大きなデチューンとランダムMPを加算すると、符号付き16ビットの音程範囲を超える場合があります。MDX側の音程値を16ビットで折り返してから、音源の使用可能な音程範囲へ制限するよう修正しました。ホスト側のキー変更スライダーはその後に適用します。

## 再出力して実行した比較

| 入力集合 | 一致 | 不一致 | 比較対象ログなし |
|---|---:|---:|---:|
| LFO_Comparison | 76 | 0 | 4 |
| LFO_Signed_Probe | 58 | 0 | 12 |
| LFO_Random_Depth_Probe | 68 | 0 | 0 |
| 合計 | 202 | 0 | 16 |

比較対象ログがない16入力は、比較対象ツールがMA4～7を拒否したものです。成功件数には含めません。Random_DepthとSignedは2回の参照記録の対象状態も一致しています。

比較はテンポ200・4 MHzで所定の57,344 OPMクロック間隔ごとに、同時刻の全書き込みを適用した後の対象レジスタ状態を調べます。MPはKC/KF、MAはキャリアTL、MHは対象のハードウェアLFO設定レジスタです。初期化・終了処理は対象外。全レジスタの書き込み順、全楽曲、全音声の完全一致を主張するものではありません。

負のMA三角波を使用する楽曲の対象区間（入力CRC32 AAE6F196）も再出力し、3キャリア×192クロック＝576点の一致を維持しました。楽曲データ・曲名は配布物に含みません。
